# Stage 9 — Portfolio and Career

**Time:** ongoing  
**Goal:** demonstrate decision-making and delivery, not tutorial completion.

## Choose a target

| Target role | Strongest evidence |
| --- | --- |
| Data analyst | SQL, decision-focused analysis, dashboards, communication |
| Data scientist | experimental thinking, baselines, statistics, error analysis |
| ML engineer | tested pipelines, serving, CI/CD, monitoring, system design |
| AI/LLM engineer | retrieval/evaluation, secure tool use, latency/cost, production app |
| Applied scientist | papers implemented, rigorous experiments, ablations, writing |
| Domain AI specialist | domain metric, workflow integration, adoption and risk controls |

## Portfolio composition

Publish 3–5 excellent projects:

1. one data/analysis project;
2. one classical ML project;
3. one specialization project;
4. one production-quality capstone;
5. optionally, one collaboration or open-source contribution.

Each project should meet the [project standard](../projects/project-standard.md).
Two deep projects are more convincing than ten tutorial clones.

## Case-study structure

1. Context and user
2. Decision/problem and constraints
3. Data source, license, quality, and leakage risks
4. Baseline and success metrics
5. Alternatives and trade-offs
6. Implementation and architecture
7. Evaluation and error analysis
8. Deployment/usage evidence
9. Safety, privacy, fairness, and limitations
10. Result and next experiment

## Interview preparation loop

- **Python/SQL:** timed practice and code review
- **ML:** metric/model selection, leakage, validation, debugging
- **Systems:** data/model lifecycle, scale, reliability, cost, monitoring
- **Projects:** 2-minute summary, 15-minute deep dive, failure story
- **Behavioral:** situation, action, evidence, reflection

## Completion test

Ask three reviewers—an engineer, a domain stakeholder, and a learner—to reproduce
and critique your capstone. Resolve high-impact issues and record the changes.
