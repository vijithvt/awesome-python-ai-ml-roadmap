# Path — Software Engineer to AI Engineer

Use this if you already build software but are new to applied ML.

**Expected duration:** 5–7 months at 8–10 hours/week.

## Diagnostic shortcut

Complete these without a tutorial:

1. Package a typed Python CLI and write five meaningful tests.
2. Join and aggregate three tables using SQL.
3. Explain leakage and produce a train/validation/test split.
4. Containerize a small API and add CI.

Study only the failed areas in [Python](../roadmap/01-python-foundations.md) and
[data foundations](../roadmap/02-data-foundations.md).

## Recommended order

1. [Stage 0](../roadmap/00-start-here.md), focusing on Python tooling
2. Python/data diagnostic remediation
3. [Math for ML](../roadmap/03-math-for-ml.md), implementation-first
4. [Classical ML](../roadmap/04-machine-learning.md)
5. [Deep learning](../roadmap/05-deep-learning.md)
6. [LLM/GenAI](../roadmap/06-llms-and-genai.md) or another specialization
7. [MLOps](../roadmap/08-mlops-production.md), applied throughout
8. [Portfolio](../roadmap/09-portfolio-career.md)

## Use your existing advantage

Bring engineering discipline to AI: schemas, tests, CI, observability, security,
failure handling, latency, cost, and maintainability. Add ML discipline that ordinary
software tests do not cover: statistical validation, leakage prevention, dataset/model
versioning, evaluation slices, drift, and human review.

## Capstone recommendation

Build an AI feature inside a credible product workflow rather than a notebook-only
demo. Include authentication/authorization, evaluation gates, fallbacks, monitoring,
and an operational runbook.
