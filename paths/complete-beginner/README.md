# Complete Beginner Handbook

This path assumes curiosity, not prior coding. It is designed for school/college
learners, non-technical professionals, career switchers, and employees who need a
safe route into data and AI.

## What this path can and cannot do

It can provide the order, selected learning material, exercises, checkpoints,
projects, certification choices, and job-readiness criteria. It cannot replace
deliberate practice, feedback, professional experience, or the documentation of
fast-changing tools.

## Choose a destination, not a permanent identity

Start with one of these:

- **Data analyst:** quickest path to working with data; strong SQL, spreadsheets,
  visualization and communication.
- **Junior data scientist:** statistics, experimentation and classical ML in
  addition to analysis.
- **Python automation developer:** Python, APIs, testing and business automation;
  a useful bridge into AI engineering.
- **ML engineer:** longer engineering route covering deployment, pipelines and
  operations.
- **AI/GenAI application engineer:** software engineering plus LLM integration,
  retrieval, evaluation, safety and cost control.

You may change the destination after completing the common foundations.

## Required learning loop

For every topic:

1. **Preview:** identify the outcome and vocabulary.
2. **Learn:** use the single primary resource listed for that week.
3. **Reproduce:** type and run a small example.
4. **Vary:** change inputs, constraints or implementation.
5. **Build:** solve the weekly lab without step-by-step copying.
6. **Test:** prove expected, edge and failure behavior.
7. **Explain:** write a short explanation in your own words.
8. **Reflect:** record the error that taught you the most.

## Weekly schedule options

### Sustainable — 7 hours

- 1.5 hours concept learning
- 2 hours guided practice
- 2.5 hours exercises/project
- 1 hour review and learning log

### Career-switch — 12 hours

- 2 hours concepts
- 3 hours guided practice
- 5 hours project work
- 1 hour interview/communication practice
- 1 hour review

### Intensive — 20 hours

Do not double the amount of content. Use the extra time for deeper projects,
debugging, mathematics, peer review, open-source contribution, and communication.

## Setup choices

### Browser-first

Use [Google Colab](https://colab.research.google.com/) for Python/data/ML and
[GitHub Codespaces](https://docs.github.com/en/codespaces) when available. This is
the fastest start but does not remove the need to learn local environments.

### Local-first

Install:

- [Python](https://www.python.org/downloads/)
- [Git](https://git-scm.com/downloads)
- [VS Code](https://code.visualstudio.com/)
- [uv](https://docs.astral.sh/uv/) for environments/dependencies
- [Docker Desktop](https://docs.docker.com/desktop/) later in the path

Follow [Stage 0](../../roadmap/00-start-here.md) for the first repository.

## When you may skip material

Skip only after completing the related diagnostic challenge without tutorial,
AI-generated solution, or copied code. If you can perform the task but cannot explain
your choices, review the concepts and proceed quickly.

## How to use AI without losing the skill

Use the repository's [AI-assisted learning protocol](../../guides/ai-assisted-learning.md).
During checkpoints, AI may clarify the question but must not generate the solution.
Afterward, use it for code review, alternative approaches, edge cases, and quizzes.

## Getting help effectively

When asking for help, provide:

1. intended behavior;
2. minimal code;
3. exact error;
4. environment/version;
5. input and expected/actual output;
6. what you already tried;
7. your current hypothesis.

Useful communities include
[Python Discussions](https://discuss.python.org/),
[Stack Overflow](https://stackoverflow.com/help/how-to-ask),
[Hugging Face forums](https://discuss.huggingface.co/), and project-specific GitHub
Discussions. Follow each community's rules and never share private data or secrets.

## Graduation standard

You finish this path when you can:

- independently frame and deliver one useful project;
- write readable Python and SQL;
- prevent common leakage and evaluation errors;
- use Git, tests, environments and documentation;
- build and explain a baseline before complex models;
- expose a model or AI workflow through a tested interface;
- discuss privacy, bias, security, limitations, latency and cost;
- show 3–4 reproducible projects tailored to a target role;
- solve the [job-readiness](job-readiness.md) gates.
