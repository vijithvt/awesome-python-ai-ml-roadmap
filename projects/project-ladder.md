# Project Ladder

Choose projects relevant to your desired role or domain. Do not build every project.
Advance when you meet the [project standard](project-standard.md) at the appropriate
depth.

## Level 1 — Starter

| Project | Core skills | Stretch |
| --- | --- | --- |
| Log analyzer CLI | files, regex, collections, tests | streaming + anomaly rules |
| Data quality reporter | schemas, validation, CLI | HTML report |
| Expense categorizer | functions, CSV, rules | API + SQLite |
| Public-data explorer | pandas, SQL, charts | scheduled ingestion |

## Level 2 — Core ML

| Project | Minimum baseline | Evaluation focus |
| --- | --- | --- |
| Churn/attrition risk | majority + logistic regression | calibration and threshold costs |
| Delivery-delay prediction | historical average | temporal split |
| Support-ticket routing | TF-IDF + linear model | class imbalance, confusion pairs |
| Energy forecasting | seasonal naive | backtesting |
| Product recommendation | popularity | ranking and cold start |
| Network/log anomaly detection | rules/statistical threshold | alert precision and investigation value |

## Level 3 — Applied AI

| Project | Must include |
| --- | --- |
| Cited policy/document assistant | retrieval metrics, citation verification, abstention, injection tests |
| Visual defect classifier | source-aware split, robustness, error gallery |
| Training gap recommender | transparent rules baseline, skills taxonomy, human approval |
| Meeting/action extractor | structured schema, multilingual cases, privacy controls |
| Demand forecasting service | backtesting, prediction intervals, drift plan |
| Domain knowledge search | permission-aware retrieval, provenance, relevance evaluation |

## Level 4 — Production capstones

Upgrade one applied project with:

1. versioned ingestion/training/evaluation pipelines;
2. experiment tracking and promotion gate;
3. tested batch or API inference;
4. container and CI;
5. authentication/permissions where required;
6. monitoring, alert, rollback, and incident runbook;
7. load/cost report;
8. threat model and system/model cards;
9. usability feedback from at least three target users.

## Good reference repositories

Study architecture and practices; do not present clones as original work.

- [scikit-learn examples](https://scikit-learn.org/stable/auto_examples/)
- [PyTorch examples](https://github.com/pytorch/examples)
- [Hugging Face notebooks](https://github.com/huggingface/notebooks)
- [Made With ML](https://github.com/GokuMohandas/Made-With-ML)
- [Full Stack Deep Learning course](https://github.com/full-stack-deep-learning/fsdl-text-recognizer-2022-labs)
- [FastAPI full-stack template](https://github.com/fastapi/full-stack-fastapi-template)

Check each repository's current license and maintenance state before reusing code.
Credit the source and explain your own changes.
